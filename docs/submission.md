## 项目摘要

CJ-DocGuard 是以仓颉原生实现的文档与示例验证工具。它从真实 AST 提取显式公共接口，将登记示例在实际 SDK 下独立编译运行，保存输出、退出码、断言和输入指纹。接口、示例、配置或工具链变化后，旧成功对当前项目失效；最新失败或未完成尝试不能被历史成功掩盖。静态报告和 AI 查询分别标明证据边界。

面向仓颉库维护者、使用陌生接口的开发者与 AI 编码助手，产物可以持续用于发布检查、内部开发、作品集及开源复用。没有宣称拿奖概率或首次发明文档生成/MCP。

## 答辩可讲清的关键取舍

| 问题 | 回答依据 |
|---|---|
| 为什么原生 AST？ | 保留声明结构和位置，避免把正则匹配当成语法理解；不声称完整语义分析 |
| 为什么全项目失效？ | 首版减少漏依赖误放行，代价是查询时内容指纹和重验耗时 |
| 为什么成功后仍显示未知？ | 运行事实与当前输入充分性分开；外部输入未审核时不把一次运行当当前保证 |
| 为什么不能返回历史成功？ | 最新登记尝试优先，失败/取消/进行中都必须可见 |
| 为什么 C/Python？ | C 负责 Unix 进程组资源控制；Python 负责构建/协议；核心判断均为仓颉 |
| AI 改善效果证明了吗？ | 已做 30 题成对受控实验：基础组和证据组功能成功均为 30/30；计入禁止工具调用后分别为 30/30 和 29/30。此轮未显示改善，且只适用于本轮任务与模型条件。见 [AI 评测](ai-evaluation.md) |

```bash

git archive --format=zip --prefix=cj-docguard/ \
  --output="build/release/cj-docguard-source-$(git rev-parse --short HEAD).zip" HEAD
```
