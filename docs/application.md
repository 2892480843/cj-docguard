一、项目概述
1. 项目一句话定位：CJ-DocGuard 面向仓颉库维护者与 AI 编码助手，生成接口文档，实际编译运行登记示例，并仅返回与当前源码、SDK（软件开发工具包） 和断言匹配的有效运行证据。
2. 项目开发背景：文档示例可能随接口和 SDK 更新失效，历史成功也可能掩盖最新失败。项目将接口、源码、示例、工具链和验证结果绑定在一起，让维护者和 AI 助手可以核查证据来源。已有文档工具和 AI 框架，因此本项目不主张该领域空白或首次发明。
3. 项目核心目标：基础目标是可检索的接口与示例文档、双 SDK 编译运行、链接检查和严格检查；进阶目标是内容指纹失效、最新尝试优先、只读 AI 查询和有效示例包导出。支持范围以实际验收为准。
二、需求分析与适用人群
1. 目标用户：需要维护仓颉库文档的作者、排查 SDK 兼容问题的开发者，以及需要可信示例的 AI 编码助手。工具适合明确批准本地代码执行的项目维护流程。
2. 开发痛点：声明与文档缺少对应关系；代码例子未经实际执行；SDK 版本信息不完整；修改后仍引用旧成功；最新失败被历史结果遮盖；共享代码缺少可复现的输入和断言。
3. 解决方案：从原生语法树提取声明和位置，按配置独立运行示例；绑定源码、配置、工具和 SDK 摘要；修改后拒绝旧证据，优先呈现最新尝试；用只读查询和 export 提供可追溯内容。未知输入不晋升为可信通过。
三、作品核心能力与功能设计
1. 基础通用能力（作品核心必备功能，保障可用、好用）
（1）能力一：接口文档与导航。使用 std.ast 提取显式公共声明、参数、返回类型、注释和位置，输出 JSON、Markdown 和离线 HTML 搜索；运行 build 生成接口、源码与示例索引。支持声明子集，尚不提供完整语义推断。
（2）能力二：真实示例验证。verify 在登记 SDK 下逐例编译运行，核对输出、退出码和断言并保存日志；check --strict 返回 0、1 或 2，分别表示满足要求、要求未满足、环境或配置异常。仅编译项单独标注。
2. 创新特色能力（赛事加分核心，重点填写）
（1）创新点一：针对当前输入的证据准入。全项目与工具内容变化会使旧证据失效；最新失败、取消或未完成尝试阻断历史成功，避免使用过期结果。完整性检查覆盖快照、命令阶段日志和断言。其代价是内容摘要检查和重验开销。
（2）创新点二：从查询到复现的闭环。三个只读 MCP（模型上下文协议） 工具提供接口与当前运行证据，原生 export 仅导出当前有效单例的冻结源码、实际编译单元、脚本及清单。导出后可使用对应 SDK 独立重建，不将登记断言外推为接口全行为保证。
四、仓颉语言核心特性应用
1. 仓颉原生语法树：std.ast 解析声明结构，保存泛型、重载、显式类型、源码位置及提取诊断；用人工符号清单和真实 SDK 测试核对支持子集，避免把文本匹配当成完整语法理解。
2. 静态类型与泛型：配置、JSON 树及证据状态使用明确的数据类型；健康项目覆盖泛型函数和容器、结构体、枚举、接口、可选返回值与回调。两个真实 SDK 独立执行相同登记断言。
3. 异常处理与模块化：配置、提取、平台、证据、报告及导出分模块实现；捕获异常并附操作阶段，拒绝无效参数、破损证据和越界路径。Unix 进程监督器对超时与子进程组作资源控制，但不宣称安全沙箱。
开发技术栈与工具：核心为 Cangjie 1.1.3/1.2.0；C 实现 Unix 进程监督，Python 标准库负责构建、测试、集成和只读 MCP 适配。使用实际 SDK 的 cjc/cjpm。许可为 Apache-2.0；上游样例保留固定提交与各自 MIT/Apache-2.0 许可。
五、库性能与兼容性设计
1. 内存实测：308 次历史隔离副本、128MB 堆预算，旧版 check/verify 内存不足；流式报告修复后 query/verify/check 均退出 0，历史保留。默认堆旧异常唯一根因仍未知，详见 docs/memory-diagnostics.md。
2. 兼容性：实际验证 macOS arm64 与 Ubuntu 22.04 Linux aarch64，分别使用 1.1.3/1.2.0 双 SDK。未验证的架构、Windows、鸿蒙、外部依赖及多包构建不列为支持。Linux 原始身份与日志见 docs/linux-verification.md。
3. 稳定性：严格配置、命令允许列表与路径边界；执行前登记，超时取消清理，校验日志和快照摘要，保留完整矩阵分母。失败、未知、缺断言和仅编译均不晋升为运行证据。
六、使用说明与落地场景
1. 快速接入：安装指定官方 SDK，运行 python3 scripts/dev.py build；在独立可信项目配置 sources、documents、sdks、examples 和输出断言，运行 verify --matrix，再运行 check --strict。只读 AI 接口配置和调用见 skills/cj-docguard/SKILL.md 与 docs/query-options.md。
2. 落地场景：库发布前检查文档与 SDK 示例；团队迭代时拒绝过期验证；学习项目查看声明与源码；向 AI 助手提供可复现证据；开源维护者导出最小复现包并保存不同版本的报告差异。暂未证明第三方实际采用。
3. 核心价值：开发者可以依据可查日志和断言判断示例是否适用于当前工程；维护者能够保留完整失败历史与版本差异；AI 工具可以复用受约束的只读证据服务。模型生成成功率变化以实际对照实验为准，不预先宣称提升。
