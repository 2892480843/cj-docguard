# 决赛网页路演：6～8 分钟操作脚本

以 **CJ-DocGuard 解决了什么、如何实现、实际价值与边界** 为主线。本脚本依据负责人提供的决赛通知准备：按 6～8 分钟演示，PPT 参考模板与章节可自行调整；正式决赛日期和材料收集时间另行通知。10 月 31 日是准备目标。

源码身份、最终测试结果和公开克隆回执以[决赛证据目录](../submission/finals-2026-10-29/README.md)为准；旧初赛视频与 PPT 继续归档，本脚本没有声称已制作新成片或提交材料。

## 演示前准备

1. 按[评委指南](judge-quickstart.md)从公开仓库克隆，登记两版仓颉 SDK（软件开发工具包），选择兼容的 Apple 系统 SDK，构建并启动网页工作台。
2. 在独立健康演示副本完成一次“诊断环境 → 构建索引 → 运行验证 → 检查证据”，确认页面标明仓颉服务端、实际 SDK 和平台。默认健康样本预期 28 格，其中 26 格运行验证、2 格仅编译；实际页面与日志不符时，先排查，不能套用截图数字。
3. 按评委指南生成并登记真实库原版和显式 local fixed 副本，保留各自配置路径、最新任务与完整矩阵。预期原版 36/40 当前有效、4 格断言失败；显式修复版 40/40。编排脚本结束成功不等于原版断言通过。
4. 打开链接检查样本 `examples/link-checks/docguard.toml` 对应项目；样本刻意含负向链接。另开决赛证据目录，准备测试汇总、原版/修复版来源及补丁摘要。样本内容与执行结果以当场报告为准。
5. 保留演示副本原文件文本。只在该副本编辑，不修改真实库锁定缓存。预先完成的验证明确称为“准备阶段生成的真实记录”；现场仅点击检查/查询时，不说成刚完成全部编译。

## 时间安排与讲解

| 时间 | 网页操作与画面 | 讲解重点与可核对证据 |
|---|---|---|
| 0:00～0:40 | 总览，展示当前项目、服务端身份和完整工作流 | “项目把仓颉库声明、示例及版本对应关系集中成可检索文档，并给出真实执行证据。源码改变后，旧成功会失效。” |
| 0:40～1:40 | 接口文档，搜索 `add`，展示声明、参数、返回类型、源码位置及关联示例 | 结构化文档来自仓颉声明提取。示例必须明确登记；同名成员和重载只能绑定唯一符号，未知或歧义会诊断。 |
| 1:40～2:40 | SDK 矩阵/示例详情，选具体 SDK 和平台，打开断言、编译/运行日志 | 区分 `RUN_VERIFIED`（已运行且断言满足）、`COMPILE_ONLY`（只编译）及失败。展示期望值与实际值，不把 28 格全称为行为验证成功。 |
| 2:40～3:40 | 切换原版真实库，打开 4 个失败断言；再切换 local fixed 副本并查看来源 | 两个空串分支原先把字符串字节长度当作字符码点数量。修复副本只改这两个分支，断言不改，原版失败保留；源码摘要和补丁记录可复核。 |
| 3:40～4:40 | “问题与诊断 → 链接检查结果”，运行原生链接检查，筛选 `FAIL` / `UNVERIFIED`，查看链接详情 | 实际 HTML 索引的链接按索引位置解析，文档多行标题生成完整锚点；显示原始目标、来源行和失败原因。离线外链或未支持语义保持未验证，不冒充可访问。 |
| 4:40～5:50 | 回到健康副本，“源码工作区”追加一行注释并确认保存，再运行检查和 AI 证据查询 | 内容改变即拒绝旧证据；保存源码不等于验证成功。查询指定 SDK/平台并展示拒绝原因。随后移除演示注释、保存并重新验证；若尚在编译，明确展示任务状态。 |
| 5:50～6:50 | 在当前有效项目查询具体示例证据，导出并查看包内容/既有独立重建记录 | 导出带冻结源码、环境与断言清单。重建记录与当前服务身份分开说明；只有真的在终端重新运行了包内 `build.sh`，才说“现场重建成功”。 |
| 6:50～7:30 | 历史与对比、决赛证据目录和公开源码标签 | 历史报告明确为冻结快照，不能替代当前证据。评委可从公开仓库按指南重复构建、验证、查询和导出。 |
| 7:30～8:00 | 支持范围与问答 | 当前完整验收宿主是 macOS arm64，两版 SDK。仅执行审核后登记的本地单包示例；进程监督不是操作系统安全沙箱；未声称跨平台完整通过或第三方采用。 |

现场编译耗时取决于机器；时间紧张时展示准备阶段真实记录，现场执行一次检查与只读查询，并把完整重建命令交给评委。不能用动画、旧报告或前一版结果代替当前任务状态。

## 三项修复的追问路径

| 评委问题 | 展示路径 |
|---|---|
| HTML 索引真的检查了吗？ | [原生索引回归](../tests/native_index.cj)包含实际 `href` 锚点、文件及资源路径损坏；[CLI 回归](../tests/test_cli.py)与[HTTP 回归](../tests/test_native_workbench.py)检查结果进入报告。生成后手动破坏索引再检查可检出；下一次重新生成修复输出，两步结果分别保留。 |
| 多行标题为何不会只取最后一行？ | [链接回归](../tests/native_links.cj)覆盖完整 Setext 标题段落、容器、边界和重复标题；错误的短锚点不能通过。 |
| 同名成员是否会共用一个示例？ | [绑定回归](../tests/test_bindings.py)覆盖不同文件中的 `First.read`、`Second.read`、重载、精确 ID、未知引用，以及报告/查询/导出的统一绑定门禁。 |
| 40/40 是否改了期望值？ | [真实库修复说明](real-library-unicode-repair-2026-10-29.md)、固定上游锁与本地补丁前后摘要；原版与修复副本分开保留，全部断言不变。 |

## 收尾检查

演示后恢复健康副本原文件，重新验证并检查；确认没有活动任务或未保存草稿。保留原版失败证据及带时间/源码身份的本次记录，不删除负向结果，不覆盖初赛冻结附件。演示脚本与公开发布均不等同于赛事正式提交、本人签字或发送材料。
