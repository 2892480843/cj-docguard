# AI 成对评测

本次评测比较两种输入上下文对同一个模型生成仓颉调用代码的影响。30 个任务各运行基础组和证据组一次，共 60 次独立会话。任务、随机顺序、评分条件和模型预算在生成前锁定；结果只能解释这套自建健康库及其四条隐藏输入上的表现。

## 两组条件

| 条件 | 模型可见信息 |
|---|---|
| 基础组 | 当前 `list_symbols` 查询的 47 个公共符号，仅包含声明、注释、所有者、名称、类别。 |
| 证据组 | 上述公共符号，加上当前 `get_verified_examples` 查询的 13 个 SDK 1.1.3 / macOS arm64 运行示例代码与已登记断言。 |

任务的身份、隐藏输入、预期输出和参考函数体均留在本地评分数据中，不进入提示。两组使用已登录的同一个 Codex CLI 账户，模型 `gpt-6.1-sol`、推理预算 `low`，每格单次生成，无选择性重试。完整预登记规则见 [protocol.md](../integrations/ai-evaluation/protocol.md)，数据见 [tasks.json](../integrations/ai-evaluation/tasks.json)。

## 锁定与执行

`scripts/ai_evaluation.py` 分三个阶段执行：

1. `prepare`：要求独立的原生 CLI、runner 和健康项目副本已通过 `verify --matrix`，再用当前原生查询冻结两份上下文、60 格顺序、提示、工具版本与 SHA-256 摘要。锁定文件写入后才能生成。
2. `generate`：按锁定顺序逐格调用本机 `/opt/homebrew/bin/codex`，每次在独立空目录启动临时只读会话。提示通过标准输入传递，事件、标准错误、最终响应、命令及时间独立保存。只读会话仍可能调用读取工具，因此任意模型工具事件均判该格失败。
3. `score`：只用本机真实 SDK 1.1.3 编译候选与自建库，使用项目原生 C runner 限时，运行四条隐藏输入并逐字比较标准输出和空标准错误。每格只允许一个 `answer` 函数，要求符号先经词法检查，再对 60 份候选人工检查接口调用。词法出现不能证明语义正确，编译与运行结果另行报告。

编译和运行日志、超时、退出码以及失败样本均保留在 `build/gap-closure/ai-evaluation/` 对应的 UTC 轮次目录。runner 是资源监督程序，不构成敌对代码的安全沙箱。

## 口径

成功率分母始终为每组 30。功能成功要求编译成功、运行成功、四条输出全匹配且无运行标准错误；总成功还要求符合单函数和指定接口使用规则。报告同时列出两组成功数、百分点差、成对同成/同败/仅一组成功，以及全部失败原因。

样本是同一库上的小规模便利样本，任务之间不完全独立；示例组的上下文更长，模型服务本身的随机性不可控。结果不外推到第三方项目、所有接口或获奖概率，也不作为实现 15 个百分点提升的保证。

## 本轮实际结果

2026-10-07 UTC 轮次 `build/gap-closure/ai-evaluation/2026-10-07T055856Z-pilot` 已完成 60 次独立生成及 SDK 评分。两组功能成功均为 30/30；计入禁止工具调用后，基础组 30/30、证据组 29/30，差值为证据组低 3.33 个百分点。初次自动评分的字符串插值词法误判原样保留，补回归测试后对同一批候选重算；完整命令、逐格退出码、人工接口审查及限制见 [Task 4 报告](../build/gap-closure/task-4-report.md)。

后续复用发布门槛：必须人工审查全部候选的实际接口调用，并逐格核对与自动评分一致；词法出现不足以作为调用成立的最终证明。未完成核对不得对外公布成功率。本轮 60/60 份生成标准错误含 CLI 状态库警告，原始日志保留；退出码均为 0，未证明影响评分，后续实验前先排查。
